# 專案圖片規則

## 選圖與排序

每個專案列表條目放**1–3張**，先挑能證明本案工作且可公開的素材，再依以下順序排列：

1. 現場照片：操作、示範、測試或展示情境，須與該案直接相關。
2. 實際畫面：產品／原型、操作手冊或簡報內的原始截圖。圖說說明它支援哪個操作或判斷。
3. 主架構圖與流程圖：本案元件、資料流、控制與驗證。保留第三方或團隊歸屬。

分析結果或論文原圖可作補充，明示其用途；不把靜態圖表叫成UI。只有一張合適圖就放一張，不為湊數放裝飾圖片、相同內容不同裁切或其他專案的照片。

## 公司素材的公開界線

| 可呈現 | 處理方式 | 保留在非公開來源 |
| --- | --- | --- |
| 操作層級、流程步驟、狀態、人工確認、防錯設計 | 選局部功能畫面，保留原始像素；移除瀏覽器、帳號或無關桌面 | 完整手冊、簡報、原始內部畫面及可還原的檔案 |
| 泛化設備、DEMO資料與原型 | 明示示範／模擬；示範數字不當成現場成果或模型成效 | 客戶名稱、廠區地址、個資、設備／批次序號、內網網址、憑證及權限細節 |
| 產品架構與方法關係 | 以抽象元件、流程圖與可證明的功能呈現 | 未公開演算法細節、完整參數、校準門檻、原始波形、內部部署拓樸及驗收文件 |
| 照片中的工作情境 | 必要時僅處理他人臉部及識別資訊，保留構圖 | 未評估可公開性的原照與可識別其他人的畫面 |

以裁切或不可逆遮蔽移除敏感區，不只把文字縮小、加半透明遮罩或用CSS覆蓋。公開衍生檔需移除不必要的中繼資料。不能因遮掉姓名就判定整張可公開；還要看資料、參數及現場細節。

來源位置、hash、頁碼／投影片與裁切遮蔽座標留在非公開素材記錄。公開圖說保留適當出處、角色、示範狀態及閱讀所需限制，不揭露內部路徑。

## 原圖與示意圖

- 原始截圖可以裁切／去識別，不能重繪後仍稱原始畫面。
- 當原圖含過多敏感資料，改用依有據功能重繪的互動示意；圖內及圖說都標「示意／重繪，非原始畫面」。
- 不捏造模型回答、客戶對話、準確率或正式部署。實際原型截圖仍須標原型／模擬，不能用視覺真實感代替驗證。
- 原始研究圖保留作者及第三方模型歸屬；簡化流程圖另行說明，兩者用途不同。

## 切換與放大

提供左右按鈕、目前張數與鍵盤左右方向鍵；沒有自動播放。各案獨立切換，類型／時間檢視移動條目後維持選圖。點圖開頁內浮層，×／窗外／Esc關閉，焦點與閱讀位置復原。手機不橫向溢出，垂直閱讀不受水平手勢阻擋。列印顯示全部圖、隱藏切換控制；無JavaScript仍有圖片連結。

## 依案例目的選圖

技術方法、系統演進、驗證與決策為重點的案例，優先以架構說明及流程圖呈現；沒有足夠解釋價值的控件裁切不用作UI證據。這項選擇先於圖片類型排序，排序不要求每案都有現場照或UI。

若操作介面是重要工作，保留足夠完整的分析畫面：基本資訊、主要圖表、狀態及相關操作應能互相對照。去敏以必要識別與機密參數為限，不能裁掉核心結果再稱完整介面。原圖未包含的內容不以拼接或重繪冒充同一時間的實機畫面。完整功能畫面不等於公開完整系統或手冊。

示範分析的分類占比、圖形與視窗數是畫面內容，不代表模型準確率或實地驗證成果。原圖本身有捲動裁切時保留原狀，不補造被裁掉的資料。

同一張圖在同一案例只出現一次，放在能回答問題的位置。現場照補情境，流程圖解釋機制，UI解釋操作，研究原圖補方法；不以相同圖的不同尺寸重複堆疊。
