# 專案閱讀結構與固定格式

## 首頁：快速認識

先交代定位、正式職稱、代表工作與經歷，再用六個代表案例說明能力。每案順序固定：**專案情境 → 核心問題 → 遇到困難 → 我的工作 → 成果**。研究與競賽沿用相同欄位；團隊獎項不改成個人獎項。

首頁保留代表性，完整廣度放列表，技術細節放內頁。不要在三層複製整段相同敘述。

## 專案列表：橫向比較

每案固定名稱、類型、紀錄時間、產品關係、圖片及三欄：**核心問題 → 我的工作 → 成果**。保留類型／時間檢視與分類／年份跳轉。同一個專案只有一份條目，切換檢視時移動原條目，圖片狀態也應保留。

圖片1–3張，選擇與順序依[圖片規則](MEDIA_POLICY.md)。圖片與文字形成一個條目，不額外建立重複的近期作品或代表作品列表。

## 案例內頁：逐步深入

首屏固定：類型、專案名稱、概要、我的工作、成果與狀態、紀錄時間。紀錄年不冒充專案起訖。

深入內容提供以下入口：

1. **問題與判斷**：核心問題、限制、本人作出的取捨、方法及有據結果。
2. **系統與流程**：先用文字／欄位說明輸入、處理、產出，再放本案的流程圖。明確區分資料流、控制、審查及條件分支；邏輯流程不代表部署拓樸。
3. **介面與互動**：有使用者操作設計時，放實際畫面與它如何支援工作。沒有安全原圖時用清楚標示的示意圖；純研究／離線分析不硬補UI。
4. **成果與驗證**：已完成產物、實際測試及適用範圍。研究、原型、整合、現場示範、正式部署與正式驗收分開記錄。

原始架構圖、模型圖、現場照片及領域深入章節按用途保留，不重複放同一張流程圖。第三方模型、共同作者、工程夥伴及AI協作保留必要歸屬。

## 共通規則

- 中英頁成對，頁首、相關案例、圖說、按鈕與替代文字齊全；切換保留所在案例及可用片段。
- 同層字級、欄位、留白與麵包屑對齊使用共用樣式。
- 不編造準確率、效益、錄取率、ATS通過或驗收狀態。
- 圖片點開仍留在原頁。圖片不得靠裝飾取代系統說明。
