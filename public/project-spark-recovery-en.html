Key design decisions

Make distributed infrastructure reproducible for the team

ChallengeThe course system needed multi-node processing and a reproducible cluster.

Approach and tradeoffsI used Vagrant to build a master and two workers on one computer, configuring connections, Java/Spark and startup instructions.

ResultBuilt a documented, runnable cluster supporting integration of the team's data-recovery pipeline.

Explain separate modules as one end-to-end flow

ChallengeAfter cluster startup, different members still owned collection, storage, recovery and charts. The demo needed to explain how data moved between them.

Approach and tradeoffsI handled GitHub and the demonstration video. The team README retained module instructions, while the demo connected raw data, imputation and charts. Teammates implemented models, crawlers and databases.

ResultThe team delivered a demonstrable course system with distinct cluster and integration-demo outputs from me. Imputed values remain model predictions.
