專業摘要

現任皓博 Data Scientist，擔任 Harbor AI 2.0 工業監控與出廠品質檢測兩項產品的主開發者與負責人。把現場需求轉成規格、操作流程與驗收條件，主導演算法設計與實驗，整合訊號分析、模型驗證與 Python 後端。

獨立主導 MCIENet 碩士論文，涵蓋多尺度 CNN、資料流程、消融及跨資料集評估；另具客流估計、金融文本與人物再辨識研究及專案經驗。

技術能力

  • 資料分析與工業診斷： Python、NumPy、pandas、SciPy、scikit-learn、PyTorch；振動、局部放電相位圖譜（PRPD）、FFT、WAV、剩餘使用壽命（RUL）、統計檢定與效果量、CNN、消融及可解釋性分析（XAI）。
  • AI 與報告系統： LangChain、LangGraph 原型驗證、診斷報告服務整合、vLLM 端點能力驗證、OpenAI-compatible APIs、數值分析與 LLM 文字說明分離、多設備隔離、失敗備援與人工驗證。
  • 後端與產品： Django、Django Ninja、Pydantic、PostgreSQL、Redis、RabbitMQ、REST API、非同步工作流、React、TypeScript。
  • 工程與交付： Docker、Docker Compose、離線與跨架構安裝、版本更新與回復、資料遷移、Git、自動化測試、AI agents 與人工發布審查。

工業智慧監控平台

  • 產品與操作流程： 擔任產品主開發者與負責人，主導產品、領域設計及開發。將振動、局部放電（PRPD）、RUL、趨勢與資料品質轉為設備／感測器狀態、事件分析和操作流程，整合報表、圖表與 API。
  • 新舊系統演進： 設計設備資料與使用者設定的同步保護，避免舊系統覆寫新平台設定；推進設備控制權轉移、事件資料來源切換及資料遷移。感測器對應不明時停止匯入，補正後重新驗證；目前 2.0 已可獨立於 1.0 運作。
  • 分析任務與排程： 負責 Django 非同步工作流、跨服務整合與感測器排程，定義 API、資料存取、檔案引用、任務生命週期及失敗行為。以資料庫保存排程及執行狀態，整合手動觸發、批次與歷史查詢，依資料可用性選擇彙總或 WAV 輸入。
  • 資料傳輸與保存決策： 參與 MQTT／HTTP 的即時預覽、資料補送及控制分工，RabbitMQ 佇列／訊息處理流程，以及特徵、WAV 與 FFT 資料保存的取捨；讓日常監控與需要原始證據的深入分析各有資料依據。
  • 振動事件鏈路（平台流程）： 告警後等待波形到齊，限定事件區間分析並將摘要回寫至感測器頁；分開呈現分析執行狀態與資料完整度。
  • 邊緣資料與控制： 負責 Gateway 資料接收契約，定義資料與控制的責任分工、完整性、去重、容量與驗證條件，完成跨組介面對齊與服務實作交接。另參與版本分發及 RUL 閾值回饋。

設備出廠品質檢測方案設計與交付

  • 需求與方案發想： 擔任出廠品質檢測產品主開發者與負責人。以既有感測器滿足多機型檢測需求，主導從量測計畫、基準比對、判定到偏離分析的方案及系統開發。
  • 領域模型與三層 UI： 定義計畫 → 工單 → 待測物的關係，以計畫清單、工單作業與待測物看板組織操作；將機型的階段與量測點納入規格，讓同一套感測治具支援逐件檢測與追溯。
  • 品質判定演算法與實驗： 主導良品基準、特徵比對和門檻設計。依機型、階段與測點比對量測特徵，透過門檻與特徵偏離支援 OK／NG 或無法判定，保留缺測與基準不足等原因。
  • 分析與偏離定位： 規劃從整體判定深入階段、測點與特徵差異的資料分析，讓使用者追查偏離基準的位置；特徵差異不直接當作已確診的故障根因。
  • 操作與量測防錯： 收斂原先 5–6 層及循環導航，整合報告、複查與基準管理，加入主要動作、鍵盤、狀態及感測器提醒。分開安裝確認與正式量測，以感測器及位置示意防止錯誤配對；獲 DQA 定性正面回饋。
  • 現場導入與教學： 2026 年 10 月 12 日到場示範並教導使用者操作，定位主機時間偏移造成的連線中斷，完成現場與後續修正，將客戶回饋帶回產品開發。
  • 階段驗收與交付： 主導測試版本、操作手冊、交測與現場交付。第二階段軟體功能驗收已完成。
  • 第三階段 QC 研究（進行中）： 分析量測資料與特徵，研究良品基準的穩定性、OK／NG 的誤判與無法判定情境。準備與客戶對齊補收資料、品質標記、QC 問題與驗證範圍，辨識成效待驗證。

工業分析、模型驗證與診斷報告

  • 局部放電指標設計與實驗： 從原始波形追查相位解析局部放電（PRPD）指標，區分取樣點數與放電事件。比較時間窗與有效波形覆蓋的影響，評估指標能支持的診斷結論。
  • RUL 假設與實驗審查： 發現測試常數被當成觀測資料，撤回原分析結論並要求多參數、多曲線及正反向消融；讓研究 notebook 直接呼叫產品程式，檢查快速劣化漏報、健康序列誤報及實作差異。
  • 診斷與輸出規則： 整合前處理、有效運轉區段、故障分類、ISO 嚴重度、RUL 及報告，區分故障型態、嚴重度與剩餘時間；檢查取樣、覆蓋、選擇偏差及分母，資料不足時降級輸出並保留分析依據。現場壽命真值與信心校準仍待建立。
  • 報告服務產品化： 主導分析方法、報告結構及品質條件，從案場報告建立可重用流程；透過 LangChain、LangGraph 原型驗證節點契約、多設備隔離、局部重產及備援，再推進服務與平台派工、DOCX 報告及下載功能整合。數值與分類由分析節點產生，LLM 負責文字說明。
  • 模型服務能力驗證： 完成 vLLM 端點的 chat、embedding 及 tool calling 驗證，分別檢查連線、功能與語意結果，作為服務整合依據。

研究實驗方法｜2020–2024

  • 在有限 GPU 資源下以 Shell 安排並行實驗，曾於同一 GPU 執行兩組不同參數，分開保存紀錄及模型檢查點。
