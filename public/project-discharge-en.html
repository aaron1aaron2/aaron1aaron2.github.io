The problem

Turn equipment alarms into traceable partial-discharge analysis jobs, showing both the analytical result and data completeness.

Inputs, process and outputs

Inputs
Equipment alarm events and event-window waveforms uploaded incrementally.
Process
Track new events by arrival order and dispatch after the file set stabilizes. Record execution and completeness separately.

Key problems and my approach

Answer execution success and data completeness separately

Waveforms arrive file by file. Existing files do not mean an event is complete; immediate dispatch can present partial analysis as a complete result.

I contributed domain, dispatch and validation judgments. File-set stability governs dispatch, with execution state and completeness retained separately. The team and agents adjusted waiting behavior using actual arrival delays and allowed success with partial data.

The platform changes were merged and exercised on complete, partial, missing, overflow and multi-sensor cases. Device-triggered recording and further integration remain prerequisites.

Track backfilled events by arrival order

Events uploaded by an offline device may have old timestamps. Resuming from the latest event time can permanently miss newly arrived records.

The team and agents changed resumption to event IDs, using arrival order to discover events and event time to select analysis windows. Each sensor dispatches and terminates independently; checks cover cursors, file-count semantics and statistics.

Verified cursor positions, file counts and statistical semantics in multi-sensor and missing-data cases so late arrivals are not ignored because their event timestamps are older.

Results and validation

Integrated platform dispatch and checked complete, partial, missing-data and multi-sensor cases with real data. Device recording and frontend integration remain subsequent work.
